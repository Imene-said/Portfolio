La compétence

Réaliser la documentation technique d’un projet

Dans le cadre du projet nommé SAE 4.01, j’ai réalisé une documentation technique afin de garder une trace du travail effectué et de permettre à une autre personne de comprendre plus facilement la solution mise en place.

L’objectif n’était pas seulement de présenter le résultat final, mais surtout d’expliquer les différentes étapes, les choix réalisés et les éléments nécessaires pour reproduire ou modifier la solution.

01

L’objectif de la documentation

La documentation permet de regrouper les informations importantes du projet dans un même support.

Je voulais qu’une personne qui n’a pas participé directement au projet puisse comprendre son fonctionnement sans avoir besoin de me demander chaque information.

02

Les informations présentées

J’ai sélectionné les informations qui me semblaient les plus utiles pour comprendre le projet et son fonctionnement.

La documentation présente notamment l’architecture, les configurations, les équipements utilisés ainsi que les différentes étapes réalisées.

03

La structure du document

J’ai organisé la documentation en plusieurs parties afin de rendre la lecture plus simple. Chaque partie correspond à une étape ou à un élément important du projet.

Présentation Architecture réseau Configuration Sécurité Tests Résultats
04

Les schémas et illustrations

Pour rendre les explications plus faciles à comprendre, j’ai utilisé des schémas permettant de représenter l’organisation du réseau et les différents équipements.

Ces représentations permettent d’avoir rapidement une vision globale de l’installation avant d’entrer dans les détails techniques.

05

La partie technique

Une partie importante de la documentation concerne les configurations réalisées pendant le projet.

J’ai expliqué les paramètres importants et les différentes étapes de configuration afin que la solution puisse être comprise et, si nécessaire, reproduite par une autre personne.

06

Les difficultés rencontrées

La principale difficulté a été de trouver le bon niveau de détail. Il fallait expliquer suffisamment les manipulations sans rendre la documentation trop compliquée à suivre.

J’ai également dû faire attention à présenter les informations dans un ordre logique afin que quelqu’un puisse suivre le projet sans se perdre dans les détails techniques.

Ce que je retiens de cette compétence

Cette réalisation m’a permis de comprendre qu’une bonne documentation fait partie intégrante d’un projet réseau. Elle permet de conserver une trace du travail réalisé et facilite les interventions futures.

J’ai également appris à mieux organiser mes informations et à expliquer des éléments techniques de manière plus claire. Pour moi, une documentation réussie doit être suffisamment précise pour être utile, mais aussi suffisamment claire pour rester facile à consulter.
