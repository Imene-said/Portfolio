Appliquer une méthodologie de tests de pénétration

Dans le cadre d’un exercice de cybersécurité de type Warbox, j’ai réalisé un test de pénétration sur l’infrastructure d’une entreprise fictive afin d’identifier différentes vulnérabilités.

J’ai utilisé une machine sous Kali Linux ainsi que plusieurs outils permettant d’analyser les services et les applications exposés.

Environnement de test

Cette image peut présenter une capture de mon environnement Kali Linux, d’un scan Nmap ou des différents outils utilisés pendant le test de pénétration.

Exemple de réalisation lors du test de pénétration

01

Le contexte

Le projet consistait à analyser une infrastructure fictive afin de rechercher des failles de sécurité pouvant être exploitées par un attaquant.

L’objectif était de reproduire différentes étapes d’un test d’intrusion dans un environnement contrôlé et de comprendre les risques liés aux mauvaises configurations des services.

02

L’objectif

L’objectif était de se placer dans la situation d’un attaquant afin d’identifier les points faibles de l’infrastructure.

Cette démarche permet ensuite de comprendre les risques pour le système d’information et de proposer des mesures permettant de corriger les vulnérabilités découvertes.

03

La reconnaissance

J’ai commencé par une phase de reconnaissance afin d’identifier les machines accessibles et les services présents sur l’infrastructure.

J’ai notamment utilisé Nmap pour analyser les ports ouverts et déterminer les services disponibles sur les différentes machines.

Kali Linux Nmap Analyse réseau
04

L’analyse des services

Après avoir identifié les services disponibles, j’ai analysé leur configuration afin de rechercher d’éventuelles failles de sécurité.

Pour la partie web, j’ai utilisé WPScan afin d’analyser l’installation WordPress et de rechercher des informations ou des fichiers accessibles publiquement.

WPScan WordPress Audit web
05

Les tests sur les services

J’ai également vérifié la configuration du service FTP afin de déterminer si une connexion anonyme était possible.

Cette vérification m’a permis d’identifier une mauvaise configuration donnant accès à un fichier qui n’aurait pas dû être accessible.

Cette situation montre l’importance de correctement sécuriser chaque service exposé sur une infrastructure.

06

Les difficultés rencontrées

La principale difficulté a été d’analyser correctement les nombreux résultats obtenus lors des différents scans.

Les outils de pentest peuvent générer beaucoup d’informations. Il faut donc vérifier chaque résultat afin de déterminer s’il correspond réellement à une vulnérabilité.

J’ai également dû comprendre le fonctionnement des différents services avant de pouvoir identifier leur niveau de risque.

Ce que je retiens de ce projet

Cette expérience m’a permis de comprendre qu’un test de pénétration doit être réalisé de manière méthodique. Il ne suffit pas d’utiliser des outils automatisés : il faut savoir interpréter les résultats, vérifier les vulnérabilités et comprendre leur impact sur le système d’information.

J’ai également compris qu’une infrastructure peut être compromise à cause d’un service mal configuré, même lorsque l’application principale semble correctement sécurisée.

Ce projet m’a ainsi permis de développer ma capacité d’analyse et de mieux comprendre la démarche utilisée lors d’un audit de sécurité.
