Mettre en place un environnement de travail collaboratif

Dans le cadre de la réalisation de mon application de recherche de fichiers, j’ai travaillé avec mon groupe en utilisant un environnement collaboratif basé sur Git et GitLab.

L’objectif était de permettre à chaque membre du groupe de travailler sur le projet tout en conservant une version commune du code. Cette organisation nous a permis de partager nos modifications, de suivre l’évolution du projet et de travailler sur les différentes parties de l’application en parallèle.

Notre environnement de travail

Cette partie peut présenter une capture d’écran du dépôt GitLab du projet, de l’historique des commits ou de l’organisation des différentes branches utilisées pendant le développement.

Exemple de l’environnement collaboratif utilisé pour le projet

01

Le contexte

Dans le cadre de la SAÉ, nous avons développé une application de recherche de fichiers en équipe. Le projet comportait plusieurs parties, notamment le développement du client et du serveur en Python.

Comme nous étions plusieurs à travailler sur le même projet, il était nécessaire de disposer d’un espace commun permettant de centraliser le code et de suivre les différentes modifications.

02

L’objectif

L’objectif était de pouvoir travailler à plusieurs sur l’application sans risquer de perdre ou d’écraser le travail réalisé par un autre membre du groupe.

Nous devions également pouvoir retrouver les différentes versions du projet et identifier facilement les modifications effectuées par chaque membre.

03

Les outils utilisés

Pour organiser notre travail, nous avons utilisé Git pour la gestion des versions et GitLab comme plateforme distante pour centraliser le projet et faciliter la collaboration.

Git GitLab Dépôt distant Branches Commits Push / Pull
04

L’organisation du travail

Nous avons réparti les différentes tâches entre les membres du groupe afin que chacun puisse travailler sur une partie précise de l’application.

Les modifications étaient ensuite enregistrées avec des commits afin de conserver un historique du projet. Nous pouvions ainsi savoir quelles modifications avaient été réalisées et par qui.

05

La collaboration

GitLab nous permettait de partager régulièrement notre travail avec les autres membres du groupe. Lorsqu’une fonctionnalité était terminée ou qu’un problème était corrigé, les modifications étaient envoyées sur le dépôt distant.

Chaque membre pouvait ensuite récupérer les dernières modifications afin de continuer à travailler avec une version à jour du projet.

06

Les difficultés rencontrées

La principale difficulté a été la gestion des conflits lorsque plusieurs personnes avaient modifié les mêmes fichiers. Git pouvait alors détecter des modifications incompatibles et empêcher leur fusion automatique.

Nous avons dû apprendre à identifier les lignes concernées, comparer les différentes modifications et communiquer entre nous afin de déterminer quelle version devait être conservée.

Ce que je retiens de cette compétence

Cette expérience m’a permis de comprendre l’importance du travail collaboratif dans un projet informatique. Lorsque plusieurs personnes travaillent sur le même programme, il est indispensable d’avoir une organisation permettant de partager les fichiers et de suivre les modifications.

J’ai appris à utiliser Git et GitLab pour gérer les différentes versions du projet, mais également à mieux communiquer avec les membres de mon groupe lorsque des modifications devaient être fusionnées.

Je retiens surtout qu’un environnement collaboratif ne sert pas uniquement à stocker du code. Il permet également de structurer le travail d’équipe, de conserver un historique et de faciliter le suivi de l’évolution d’un projet.
